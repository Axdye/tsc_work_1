# 候选问题与 idea（只读研究阶段）

日期：2026-11-02。以下是可检验假设，不是已获验证的新方法或首创声明。
本阶段不训练、不运行实验。

## 已撤回的简单创新点

- “CoLLMLight 没考虑建议过时”：不成立。最终版 §4.6 已有随机额外延迟一步和邻居消息丢失测试。
- “加入多步 rollout”：不足。CoLLMLight 的 FTSample 已从快照枚举相位并多步评估。
- “给 reasoning 分步信用”：范围过宽。2026-09 ProcessLight 已提出语义步骤验证、重要性和分步优势。
- “用 RL＋LLM 门控/回退”：已有 iLLM-TSC、LA-Light、ReasonLight 等路线，以及 guarded supervision。
- 扩展调研进一步核对：VLMLight 已有视觉感知和快慢分支选择；DGLight 已有 Q-guided GRPO 与快照联合 rollout 变体；
  CFLight 已有反事实后果监督。不能把这些机制本身作为新贡献，详见 RESEARCH_EXPANSION.md。

## 推荐主问题：慢建议在真正执行时，是否仍比当前快策略更有价值？

交通变化与推理异步意味着“生成时合理”不等于“使用时有用”。
需要同时区分：内容正确、改变了动作、改善了交通、收益足以覆盖计算/延迟成本。
当前几篇代表方法分别使用 critic 分数、最优相位标签、自报 used_atr、整轨迹回报或相位一致性。
这些监督都不直接等价于“当前快策略之外，由这条建议贡献了多少实际收益”。

### 候选设计

快控制器 pi_fast：传统 RL 策略，每个合法控制时刻输出动作。
慢模块：LLM 根据历史/邻居/可选事件提出结构化协同建议 g，记录生成时刻及适用条件。
监督目标是在建议实际可用的状态 s_exec 上估计配对增益：

DeltaU(s_exec,g) = G_H(with g) - G_H(without g)

两个分支从同一交通/控制快照开始，采用一致的后续控制、需求与随机初始化。
若优化的是代价 C，则等价用 C_without - C_with。
训练轻量价值头预测该量及误差，决定采用、忽略或请求刷新；训练时有仿真分支，部署时没有未来真值。
LLM/调度器的 reward 分解为交通增益与计算成本的加减，不把“自称使用建议”当作收益。

### 为什么与几篇最近邻不同

- CoLLMLight 的 U 是 RD 自报是否使用/有用，a* 是相位标签；这里以执行时刻的配对交通后果监督建议价值。
- Traffic-R1 的 STPO 将 R_traj/T 分给每步；这里区分快策略、本次慢建议及其延迟后的局部/网络增量。
- OracleTSC 使用输出相位一致性与 hurdle；这里关注后果差异，多种相位等效时不强行把分歧解释为风险。
- ProcessLight 主要估计 reasoning step 对动作分布的影响；“改变动作”与“改善交通”仍是两种重要性。
- Guarded supervision 已研究 paired outcome 与风险门控；因此“学习一个门”不是新贡献。
  若后续成立，贡献应落在**异步建议的执行时效与跨时间信用分配**，并与此类方法直接比较。

### 必须防止的失败

1. 所有建议被拒绝，性能等于 fast-only；这是无效方法，不是稳健收益。
2. 慢模块没有比快策略更好的候选，门控本身不能凭空创造增益。
3. 只有训练时用真值与 rollout 才有效；部署价值头校准失败。
4. 分支状态没还原完整、评价 horizon 偏短或 continuation policy 不一致，产生伪增益。
5. 额外仿真预算远超基线，收益来自计算规模而非监督设计。

### 后续最小验证（尚未执行）

先冻结 fast policy 和 proposer，建立条件分布相同的 paired-state 数据；
分别比较 used_atr、token length、action entropy、预测 DeltaU 对真实配对交通增益的预测能力。
分训练路网/验证需求/测试路网，切分按 episode/seed，不能将同一快照的分支拆到训练和测试。
之后再看固定周期刷新、车流阈值触发、随机同预算、value gate、oracle gate。
除 ATT/AWT/吞吐外，报告查询率、动作改变率、采用建议后的净收益、负增益率与调用预算。
真正 oracle gate 只作为上限诊断，不能作为可部署算法。

## 备选 A：动作等效感知的 LLM RL

问题：CoLLMLight +/-1 精确标签与 Oracle 相位投票会把交通效果几乎相同的相位区别对待。
想法：以同状态 rollout 的 action-value gap 或后果分布构造软目标/等效集合，
让近似等效相位共享正信用，集中惩罚有明显交通 regret 的动作。
需要与 soft-label imitation、advantage-weighted learning 和标准 critic-guided ranking 比较。
优势：可以先固定相位空间，成本较低；风险：已有 action-gap/advantage 学习，
只把分类标签改软通常创新不足；需要证明对语言策略的训练方差/迁移有特定价值。

## 备选 B：时长一致的多路口信用分配

问题：HeraldLight 时长不同，Traffic-R1 r_t=R_traj/T 与固定步长协议不能直接统一。
想法：将 phase+duration 视为 semi-Markov action，按实际秒数累计拥堵代价，
折扣用 exp(-rho*Delta_t)，对不同路口异步事件进行交通时间归因。
需与匹配动作空间的 DynamicLight、常规 SMDP PPO、规则预测配时比较。
优势：任务实际；风险：SMDP 本身成熟，创新必须在多路口异步建议及信用归因，不能只是改 gamma。

## 推荐优先级

先研究“执行时建议增益”问题，优先固定原有相位与时长以隔离贡献。
动作等效作为低成本机制对照；可变时长作为后续扩展，避免一次改变太多变量。
ProcessLight 与 guarded-supervision 的最近邻分析必须补齐后，才能判断投稿层面的新颖性。

## 与 LA-Light 功能线对应：故障/事件下的工具信息价值

问题：一次决策的工具可能只重复读取同一缓存；传感器缺失、真实空队列和道路不可用又可能混淆。
可研究在部分观测状态下，是否需要调用能提供新增证据的工具，以及新增证据是否改变了更好的控制动作。
将工具明确分为“已有 snapshot 的不同视图”和“新增/更新观测”，记录观测时刻、缺失标记和有效期。
候选策略预测查询前后的期望交通代价差，扣除查询成本，再决定查询、等待、采用旧数据或回退。

这比给工具调用本身加正奖励更合理，也避免把 MP 建议重新读一遍当作信息获取。
应与同信息规则控制、无工具 LLM、固定工具链、随机同预算查询比较；如果完整 snapshot 已提供全部信息，
应承认没有额外信息价值，不能人为删信息只让自己的模型获得特权。
工具调用/价值信息已有大量先例；候选贡献需落实为交通事件下的观测时效、缺失语义和闭环后果，不能仅做工具封装。
此线保留 TransSimHub/SUMO 原生环境，不把数字直接与 CityFlow 比较。
