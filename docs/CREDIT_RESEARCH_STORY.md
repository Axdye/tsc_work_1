# TSC 信用分配与快慢协同：任务、相关工作与毕业设计定位

更新：2026-11-17。本文汇总前期论文/源码阅读与本轮设计。**没有新的 GPU 训练结果，也不预先声称 SOTA。**

## 1. 整体研究路线

毕业设计按两个递进的研究模块组织：

1. **共享 LLM 的多路口、多步交通控制：反事实分组 GRPO。** 融合 JS-GRPO 的仿真分支与 COMA/SocialLight 的条件贡献思想，建立可运行、可比较的环境反馈训练系统。定位为有实验验证的方法融合，不声称发明反事实信用分配。
2. **快慢协同控制：协调建议与实时执行的跨时间尺度信用分配。** 在第一部分的环境、评测和训练接口上，引入慢速协调计划、快速相位决策、建议更新与失效机制，重点研究“谁在什么时候改善了网络交通”。第二部分尚未实现，是后续研究设想。

两部分的共同问题是：网络级交通结果由多个路口、多次决策共同造成，如何把可验证的交通反馈转换为合适的策略训练信号？第一部分处理同一时间尺度上的路口决策；第二部分再处理不同时间尺度上的协调与执行。

## 2. TSC 的任务定义

### 2.1 控制对象与目标

路网记作图 \(\mathcal G=(\mathcal V,\mathcal E)\)，受控路口为节点，连接道路为边。在控制边界 \(t\)，路口 \(i\) 读取观测 \(o_{i,t}\)，选择动作 \(a_{i,t}\)。所有路口的联合动作 \(\mathbf a_t\) 改变车辆运行、排队与下游可接收容量。

完整任务是多步、部分可观测的协作控制。常见观测包括进口排队、行驶车辆、下游排队、当前相位、相位持续时间和邻居信息；目标是降低旅行与等待时间、队列、溢出和拥堵传播，并提高通行能力。

训练可以使用全局奖励，但部署时每个路口只读取规定的局部/邻居观测。训练访问 CityFlow 的完整快照是一种特权评估能力，不代表部署模型能访问未来。

### 2.2 “一步”“多步”“多模型”是不同维度

| 维度 | 选项 | 本项目第一部分 |
|---|---|---|
| 控制对象 | 单路口 / 多路口 | 多路口，默认合成 4×4 训练 |
| 环境时域 | 单次标签比较 / 连续交互 | 连续交互；策略更新后重新采集访问状态 |
| 评分时域 | 一步后果 / H 步后果 / 整段轨迹 | 主方法 H=3，包含第一步；消融 H=1、6 |
| 策略参数 | 各路口独立 / 参数共享 | 一个参数共享的 LLM，在各路口分别调用 |
| 决策角色 | 单角色 / 快慢角色 | 第一部分单角色；第二部分再引入快慢角色 |
| 动作 | 相位 / 保持或切换 / 相位与时长 / 周期与偏移 | 固定控制间隔下选四相位 |
| 输出形式 | 离散动作 / 文本与动作 token | 最多一句说明 + `<signal>PHASE</signal>` |
| RL 更新 | 静态数据 / collect-then-train / 在线交替采集更新 | 每个采集窗口冻结旧策略，分支评分后更新 LoRA |

“一个共享模型”不等于“单智能体”：多个路口仍然有各自的观测和动作，因此 COMA/SocialLight 等 MARL 信用分配研究仍然相关。一次回复很短也可以做决策级信用分配，不需要人为写长思维链。

### 2.3 四相位是什么

| 名称 | 含义 | 新实验动作编号 | Engine 绿灯相位编号 |
|---|---|---:|---:|
| ETWT | 东西向直行 | 0 | 1 |
| NTST | 南北向直行 | 1 | 2 |
| ELWL | 东西向左转 | 2 | 3 |
| NLSL | 南北向左转 | 3 | 4 |

右转由数据中的 roadLinks 决定。Engine phase 0 是基准路网的清空相位，不是第一个可选绿灯。

四相位和八相位反映允许同时放行的交通流组合不同，不意味着前者单步、后者多步。相位编号必须核对 roadnet，不能凭字符串名称套用。本实现对所支持路网检查相位与方向映射。

### 2.4 决策时机与绿灯时长

本部分固定每 30s 决策，切换时执行的 5s phase 0 **包含在 30s 内**；保持相位不插入清空。连续保持同一相位会延长实际绿灯，但模型不能直接输出任意秒数。

这是 LLMLight/CoLLMLight 公开代码的一类协议。论文正文有“30s 绿灯 + 3s 黄灯 + 2s 全红”的描述，不能直接把正文 35s 与代码 30s 视作同一时间安排。Traffic-R1 正文使用另一种时长设置。跨论文表格的数值不能直接排名。

这是一种受控研究设定，不代表工业控制仅有四选一。更灵活的相位—时长、协调周期、偏移、应急优先等应在统一动作空间和时间预算下比较。第一部分先固定动作空间，隔离信用分配的作用。

## 3. 相关工作的脉络

### 3.1 从交通规则到协作 RL

- **FixedTime**：用预设相位顺序和时长运行，提供可复查的基础对照。要比较原实现，而不是把任意轮换规则称作官方 FixedTime。
- **MaxPressure**：依据进口与出口压力选择相位，无需训练，是重要的强简单基线。其效果受压力定义、下游数据、车道统计、清空时间和相位集合影响。
- **PressLight、CoLight 等**：从交通压力奖励、邻居表示和图协作等角度改进 RL。它们表明，多路口协作不必依赖 LLM。
- **COMA**：固定其他智能体的当前动作，对目标智能体自己的动作进行边缘化，获得动作无关的反事实基线。使用学习到的 centralized Q critic。
- **SocialLight**：把邻域条件贡献用于大规模交通控制；共享策略参数、局部集中 critic，修改优势估计并结合时序学习改善训练。它已经研究空间与时间信用，以及邻居动作导致的更新方差，不能写成“早期交通 RL 没有信用分配”。

本项目继承“条件比较”的思想，使用仿真分支估计动作后果，不移植 SocialLight 的整套 A3C/critic/GAE。

### 3.2 从通用 LLM 到交通专用策略

| 工作 | 聚焦问题 | 主要机制 | 与本项目的关系/边界 |
|---|---|---|---|
| LLMLight / LightGPT | 小模型如何获得交通决策能力 | 教师轨迹、交通 critic 辅助筛选与策略优化 | 提供数据、环境、传统基线和评测代码；本项目不声称复现其教师训练 |
| Traffic-R1 | 专家规则启蒙后，如何利用真实的仿真反馈优化 LLM | 离线专家动作 GRPO，在线 STPO 与交通轨迹收益 | 启发多步交互训练；本项目的轨迹均匀奖励对照不是其官方算法复现 |
| DGLight 主方法 | 如何把交通 Q 网络的知识转为 GRPO 奖励 | 预训练并冻结 CoLight 类 DQN critic；最终相位查表评分 | 最接近的代码组织参照；本实现不训练 Q critic |
| DGLight JS-GRPO | 不使用 Q critic，能否直接用联合仿真收益训练 | 同状态联合候选分叉、短期当前策略续跑、联合收益投影到各路口动作 | 第一部分的直接方法参照；不能把多步分叉本身称为新点 |
| CoLLMLight | 协调推理能力与实时控制开销如何兼顾 | 慢协调指导 + 快速动作模块；自适应推理与训练 | 第二部分直接参照；公开 PPO 入口主要使用预生成 Best_Signal 数据 |
| HeraldLight | 从相位选择拓展到相位和时长 | 交通到达/释放预测与 LLM 相位—时长决策 | 提醒必须控制预测输入和动作空间差异，本部分不同时引入时长控制 |
| ProcessLight | 能否对交通推理过程提供更细监督 | 结构化推理、过程评价、局部与结果优势 | 说明 span/步骤奖励已有人研究；本部分先做交通动作后果，不做思维链归因 |

**Traffic-R1 的边界。** 在线阶段是多步、多路口交互；论文 STPO 将轨迹收益均分到决策步。轨迹收益来自过程中累计的拥堵反馈，不仅是结束时刻的队列。论文对路口间指标聚合和奖励广播的公开说明不足，不能断言“16 个路口固定先求和后广播”的代码细节。完整训练资产未找到可核验公开版本。

**DGLight 的边界。** 主方法初始化继承 LightGPT。效果不能全部归给新增 GRPO；源码奖励还对 Q 作 softmax/min-max 变换，不应把它的绝对值直接当 Bellman Q。JS-GRPO 附录已经执行当前策略下的多步续跑，不能用“我们首次考虑多步”区分。其稿件自称 dissertation，本文不按已核实顶会 SOTA 处理。

**CoLLMLight 的 Best_Signal。** 来自 FTSample：恢复同一仿真状态，枚举目标路口相位，其他当前动作保持可比，后续使用规则控制，比较有限步交通成本后选标签。它依赖候选动作、评分指标、horizon 和续跑规则，不是全局最优真值。公开 `ppo_ft.py` 不等于每次更新都在 CityFlow 中进行策略交互。最终论文已测试额外延迟与消息丢失，不能把“没考虑消息延迟”当后续创新。

### 3.3 LLM 信用分配研究进一步压缩了什么空间

- **GiGPO**：轨迹级与步骤级组相对优势结合，利用重复状态分组。说明“全局+局部优势加权”并非新想法。
- **CCPO**：对协作 LLM 使用反事实贡献与策略优化。说明“LLM + 反事实 + GRPO 类更新”不能声称首次。
- **C3 / Exact Is Easier**：固定历史、恢复检查点、替换动作、继续 rollout，再计算 leave-one-out 优势。正文验证两/三角色顺序协议，已明确提供检查点反事实原语。
- **AREL、STAS、TAR²**：通过学习奖励分解、时空分配等机制处理延迟团队奖励。不能把“把全局奖励分给路口和时刻”本身包装为全新问题。
- **HEDGE**：本轮仅核对公开仓库说明，其中已有异方差信用估计与收缩设计；未在本轮核验全文或理论，因此不据其 README 的效果/定理/会议声明作结论。

第一部分选择方法融合，主动承认这些先例。后续若要投稿，再研究可证明或可明确验证的新估计器；当前不把可靠性加权和自适应预算塞入实现。

## 4. 第一部分：配对路口反事实 GRPO

### 4.1 研究问题与定位

> 在参数共享 LLM 的多路口、多步控制中，控制其他路口当前动作背景的反事实分组，能否在可比较的仿真预算下提供更有效的训练信号？

这是 **JS-GRPO 框架 + COMA/SocialLight 条件贡献思想** 的任务化融合。工作量包括完整环境交互、优势构建、LoRA 更新、受控消融、统一评价和可视化，不要求提出全新的 RL 原理。

与 Traffic-R1 的粗粒度轨迹信号相比，它评价具体路口时刻的动作；与 DGLight 主方法相比，它不依赖冻结交通 critic；与 JS-GRPO 相比，它主动配对同一邻居动作背景；与 COMA/SocialLight 相比，条件后果用实际仿真分支估计。

这种设计仍适用于非 LLM 离散策略，不声称 LLM 独有的信用分配能力。LLM 在这里提供文本接口和可扩展策略载体；是否更适合复杂事件/工具信息，留给后续专门验证。

### 4.2 算法

在当前旧策略 \(\pi_{old}\) 下，保存状态 \(s_t\)，选择目标路口 \(i\)，采样 G 个回复，解析动作 \(a_{i,k}\)。对每个背景样本 \(m\)，从旧策略采样其他路口的当前动作 \(b_{-i}^{(m)}\)。

\[
Z_{i,k}^{(m)} = \sum_{h=0}^{H-1}\gamma^h r(s_{t+h}^{i,k,m}).
\]

每个分支从相同的完整 CityFlow/环境快照出发，第一步只改变目标路口动作；以后所有路口根据分支自身的新状态由冻结旧 LLM 继续决策。**不固定所有未来动作**，因为后续反应正是动作后果的一部分。

交通奖励为：每秒全网进口排队求和，在一个控制间隔内平均后取负。使用同样本下同一相位的平均交通分数，避免同一物理相位因文字差异获得不同的交通评价。非法格式执行“保持当前相位”的安全回退，并减去统一格式惩罚。所有学习对照使用相同格式惩罚参数。

组内分数 \(q_{i,k}\) 使用总体标准差：

\[
\hat A_{i,k}=\frac{q_{i,k}-\operatorname{mean}_j q_{i,j}}{\operatorname{std}_{pop,j}q_{i,j}+10^{-6}}.
\]

完整回复的每个生成 token 共享该优势。使用 token 概率比的 clipped GRPO surrogate，加相对于冻结初始基座的 KL 正则。LoRA 禁用时就是参考基座。**无语言 value head、无额外交通 critic、无 judge、无 span 奖励。**

不重新生成用于训练的回复：分支评分使用的 prompt/token 序列，与计算旧概率和梯度的序列完全一致。训练采样固定 temperature=1、top_p=1、top_k=0，避免截断采样密度与更新概率比不一致。

每个窗口评分结束后更新 LoRA，随后重新采样。部署轨迹通过当前 LLM 的实际采样动作前进，不执行“仿真找出来的最优相位”，避免把规划收益误记成策略能力。

### 4.3 估计边界

- M=1 得到的是某个邻居动作背景下的条件比较；M>1 对多个背景平均，不是精确全局因果贡献。
- 相同 Engine 快照让初始条件可比，但不能自动保证所有外生随机数都完成严格的共同随机数耦合。
- 配对有望降低有限样本噪声；并非对所有环境都保证降低方差。独立联合采样也不必然有系统偏差。
- H 截断意味着只评价有限时间后果；H 越长也可能噪声和推理开销越大。
- 奖励只依赖最终交通动作，不能据此声称识别了文字理由的因果贡献或思维链忠实性。
- 所有分支是训练开销，必须计入仿真与 token 预算；它们不属于评测时的免费能力。

### 4.4 假设、对照与消融

| 编号 | 假设/问题 | 实验 |
|---|---|---|
| RQ1 | 更细的动作后果是否改善策略 | base、trajectory、RTG、joint、paired |
| RQ2 | 收益是否来自邻居动作配对 | paired vs unpaired，保持采样次数、H、训练规则一致 |
| RQ3 | 是否需要延迟后果 | H=1/3/6；固定总仿真预算，同时报告访问状态数 |
| RQ4 | 是否需要当前策略续跑 | LLM vs MaxPressure 续跑；评测始终部署训练后的 LLM |
| RQ5 | 局部目标是否损害协作 | 全局 vs 目标路口局部队列奖励 |
| RQ6 | 多背景评估是否划算 | M=1 vs M=2；相同总预算及等窗口两种视角 |
| RQ7 | 是否真的改善信用质量 | 固定状态，多次低预算估计对比独立高预算参考的相位差排序、符号一致率、MSE 与方差 |

高预算参考依然有噪声，不称为真实因果 oracle。所有假设都允许结果为负。

### 4.5 主评测与公平性

使用同一套环境与统计实现：3600s、30s 固定边界、切换时 5s phase 0 包含于边界间隔、四相位、laneChange=True、固定终点、不截流、不排空。默认合成 4×4 训练，济南/杭州五个真实采集需求场景测试。

“真实数据”在这里指公开需求/路网数据驱动的仿真，不代表真实信号机部署或工业闭环验证。

- **ATT**：上游每辆车经过受控路口的到离时间差求和，再平均；未离开记录在固定终点截尾，过滤 shadow。不是排空后的完整行程时间。
- **AWT**：每个决策边界对当前 waiting_vehicle_list 的停止计时求均值，再做时间平均；不是每辆完成车辆的一生总等待。
- **AQL**：每个决策边界汇总全网进口排队，再做时间平均；不除路口数。
- 补充：非法输出率、剩余车辆、推理调用/token、训练总仿真秒数、梯度/更新、零优势组比例。

默认 3 个独立训练 seed × 3 个评测环境 seed。统计时先对每个训练实例的评测 seed 求平均，再对训练 seed 报 mean±sample SD，不能把 9 个观测当 9 个独立训练实例。传统基线单独报告环境 seed 波动。

主套件按训练总仿真秒数封顶；同时画 ATT 随实际仿真预算的曲线。配对方法分支多，因此相同预算下更新次数和访问状态数可能不同。不能同时声称所有预算维度都相等；还需报告 token、wall time，并用等窗口 pilot 辅助解释。

所有学习对照使用 Qwen3.5-0.8B、同初始基座、同 prompt、LoRA、KL、格式奖惩和评测回退。LightGPT/DGLight/CoLLMLight 论文的不同初始化或时长数值不直接搬进主表。

## 5. 第二部分：快慢思考的研究定位（设计，未实现）

### 5.1 不只增加一个慢模型

下一部分的问题可以定义为：

> 慢速协调建议持续影响多个路口、多次快速决策时，怎样识别建议的边际价值、快速模块的执行价值，以及该何时更新建议？

快慢角色不一定需要两个不同基座模型。可以同一基座、角色 prompt/adapter 分开，也可以小快速模型+较大慢模型。模型数量、角色数量、参数共享方式和调用频率必须分别说明。

### 5.2 初始设计

- **快速角色**：保持第一部分四相位/30s 的接口，读取当前交通观测、协调计划与其年龄，输出立即动作。
- **慢速角色**：面向区域/走廊输出短计划，结构化列出目标、涉及路口、服务优先级、有效条件和建议期限，而不是逐路口重复选择相位。
- **调度角色/规则**：先用固定刷新周期、拥堵阈值和事件触发作为基线，再研究是否学习何时调用慢模块。
- **可用工具**：当前/历史队列、下游容量估计、到达预测、区域拥堵检索、少量仿真反事实。工具各自记录成本、延迟和可用时间。

第一版建议 schema 可以简化为 `region`、`priority`、`valid_until`、`invalidate_if`、`reason`。输出必须经过可执行解析，不能仅凭长篇文本认为发生了协调。

### 5.3 两层反事实

1. **慢计划信用**：从计划发布时保存状态，比较“当前计划”与“另一合法计划/无计划基线”，快模块在各分支根据当前状态响应。评估跨多个快控制步的区域/网络结果，减去实际推理与通信成本。
2. **快执行信用**：在固定计划条件下，只替换一个路口的一次执行动作，使用第一部分的配对估计。避免把慢计划功劳全部算给快模块，也避免把快模块自行纠错算成计划价值。
3. **更新时机信用**：比较“此刻刷新”“继续沿用”“先调用低成本工具再决定”。时间尺度不同，应按物理秒数计算折扣和成本，避免长持续动作天然占便宜。

分支必须保存缓存计划、发布时间、版本、消息队列和工具状态。若未来声称实时异步，应显式模拟推理/工具延迟：结果在完成时才可见；仿真时钟不能为大模型免费暂停。

### 5.4 更值得深入的点

- 建议价值随交通变化衰减：不是只按年龄，而是观测到何种变化使旧计划失效。
- 协调与执行的交互：某计划只在特定快速策略下有效；单独给两个分数未必识别二者互补。
- 成本受限的慢调用：能否只在高协调需求状态刷新，提高控制收益/推理成本比。
- 记忆与 in-context evolution：存储经过交通后果验证的计划案例，按当前区域状态检索；对比固定 prompt、普通检索、带反馈记忆。记忆只来自训练/已发生交互，不读取测试未来。
- 工具选择：预测/检索/仿真各自是否提供额外信息，还是只是增加 token 或改变输入优势？做相同工具输入与调用预算对照。

### 5.5 必要对照与毕业论文连接

对照包括第一部分的单角色策略、固定周期快慢、事件触发快慢、CoLLMLight 适配、始终刷新、不刷新、关闭计划、工具逐个移除，以及延迟/消息丢失/突发需求等压力测试。

CoLLMLight 已研究推理成本并测试部分延迟/丢包，Astra 等层次交通方法也说明“多层结构+反馈”不是空白。因此第二部分应聚焦**跨时间尺度贡献与更新时机**，不能把架构名称本身当创新。

毕业论文的递进关系是：第一部分解决路口动作的环境信用；第二部分把信用对象扩展到持续计划、即时执行和调用时机。工业迁移可以作为有条件的扩展：需要真实数据许可、信号安全约束和校准仿真，不能预先承诺在线上城市道路试验。
